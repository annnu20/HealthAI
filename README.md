# AI-Powered Healthcare Diagnosis Assistant

A machine-learning app that predicts likely diseases from reported symptoms
and answers general health questions, with a Streamlit frontend.

This started as a single Colab notebook
(`AI_Powered_Healthcare_Diagnosis_Assistant.ipynb`). The original modeling
logic is unchanged — it's been split into reusable backend modules and
wired up to a Streamlit UI instead of the notebook's `input()`/`print()`
console loop.

## Features

- **Chic, themed UI** — a custom indigo/teal theme (Poppins/Inter fonts,
  gradient hero, card-based layout) instead of default Streamlit styling,
  with a clean non-technical Home page (model internals live on the About
  page instead)
- **Patient accounts** — register and log in with a username, email, and
  password (salted + hashed with PBKDF2, never stored in plain text)
- **Symptom-based prediction** — pick from 132 recognized symptoms (dropdown
  or free text), get the predicted disease with a confidence score
- **Top-3 likely conditions** with probability bars
- **Health report** — description, recommended diet, and precautions for the
  predicted condition (all 41 diseases the model can predict are covered)
- **Conversational chatbot** — handles greetings, thanks, small talk, and a
  wide range of health topics (fever, cold, cough, diabetes, malaria, COVID,
  blood pressure, cholesterol, sleep, stress, diet, and more), with a
  helpful fallback instead of a flat "I don't understand"
- **Report & scan uploads in chat** — attach a lab report (PDF), or an
  image of an X-ray/MRI/scan (PNG/JPG). The assistant acknowledges what it
  received and, for PDFs, flags which general categories of test it
  mentions — it never fabricates a diagnosis or interpretation (see
  "Report uploads" below)
- **Downloadable chat** — export the full conversation as a `.txt` file
- **Persistent history** — every prediction you run is saved to your account
  in a local database and downloadable as CSV
- **About page** — shows which model was selected and its accuracy

## Theme

The app uses a custom indigo (`#4F46E5`) → teal (`#14B8A6`) gradient theme
with Poppins/Inter fonts, applied via a single CSS block at the top of
`app.py`. The Home page uses a hero banner, a 4-card feature grid, and a
3-step "how it works" section — no model statistics or technical details,
which now live entirely on the About page.

## Report uploads — what the chatbot does and doesn't do

There's no trained image-analysis or lab-report-interpretation model in
this project, so the chatbot is deliberately honest about that instead of
faking a reading:

- **PDF reports**: text is extracted (`pypdf`) and scanned for general
  category keywords (e.g. "blood sugar / diabetes", "cholesterol / lipids",
  "kidney function") — it names categories the report touches on, never
  values, ranges, or a verdict on what's normal or abnormal.
- **Images (X-ray/MRI/scan photos)**: acknowledged and shown as a
  thumbnail in the chat, with a clear note that image interpretation
  needs a radiologist or treating doctor.
- Every acknowledgment ends by pointing back to a healthcare professional
  for the actual reading.

## Technologies used

- **scikit-learn** — Decision Tree, Random Forest, Logistic Regression,
  Naive Bayes, and SVM classifiers (best one kept by validation accuracy)
- **pandas / numpy** — data loading and processing
- **joblib** — model persistence
- **SQLite** — patient accounts and prediction history
- **pypdf** — extracting text from uploaded report PDFs
- **Pillow** — image handling for uploaded scans
- **Streamlit** — frontend

## Train the model (first time only)

The app loads a pre-trained model from `models/`; it never trains on the
fly. Generate those artifacts once:

```bash
python train_model.py
```

This reads `data/Training.csv` and `data/Testing.csv`, trains all five
models, keeps the best one, and saves it to `models/`. Re-run this any time
the data changes.

> Note: after de-duplication the training set has 304 unique rows across 41

### Model enhancement: confidence tuning

The Random Forest was tuned beyond the notebook's defaults —
`n_estimators` raised from 100 to 300, and `max_features=None` so every
tree considers all 132 symptom columns at each split instead of a random
~11. With this many sparse binary features and a small dataset, this
produces less noisy, better-calibrated probabilities without changing
validation/test accuracy. For a disease's full, characteristic symptom
set this typically lands in the 75–100% confidence range.

**Confidence naturally stays low when few symptoms are entered** — this is
expected model behavior, not a bug. For example, "itching" alone is listed
against 6 different diseases in the training data, so a model claiming
>90% confidence off that one symptom would be miscalibrated, not more
accurate. Instead of hiding or inflating that number, the Diagnose page
shows which other symptoms are commonly reported for the predicted
disease when confidence is under 60%, so you can add relevant ones and
get a sharper result — see `DiseasePredictor.common_symptoms_for()` in
`backend/model.py`.

## How the frontend connects to the backend

`app.py` imports directly from `backend/`:

- `backend.database` — `register_user()` / `authenticate_user()` for
  accounts, `save_prediction()` / `get_prediction_history()` for a
  per-user history persisted in SQLite (`data/app.db`, created
  automatically on first run).
- `backend.model.get_predictor()` — loads the saved model/encoder/symptom
  list once (cached with `st.cache_resource`) and exposes
  `predict_with_confidence()` / `top_predictions()`, which are the same
  logic as the notebook's `predict_with_confidence()` (cell 50), just
  loading from disk instead of notebook globals.
- `backend.knowledge_base.disease_details()` — same `health_data` lookup as
  the notebook's `disease_details()` (cell 56), returning a dict instead of
  printing.
- `backend.chatbot.answer_question()` — expanded from the notebook's
  keyword rules (fever, diabetes, malaria, COVID, headache, diet) to also
  handle greetings, thanks, farewells, small talk, and many more health
  topics, with a helpful fallback instead of a flat "Sorry" message.

No original prediction logic, thresholds, or knowledge-base content were
changed — only how they're invoked, displayed, and (for the chatbot)
extended.

## Accounts & data

- Passwords are hashed with PBKDF2-HMAC-SHA256 and a random per-user salt
  (260,000 iterations) — never stored in plain text.
- All data (accounts + prediction history) lives in a single local file,
  `data/app.db`. Deleting that file resets all accounts and history.
- There's no email verification or password reset flow — this is a local,
  single-machine setup, not a production auth system.

## Expected input

Comma-free list of symptom names (e.g. `itching`, `skin_rash`,
`joint_pain`) — pick them from the dropdown in the "Diagnose" page, or type
them comma-separated in the text box. Symptom names must match the
132 columns the model was trained on (underscore-separated, e.g.
`skin_rash`, not "skin rash"); the free-text box also accepts spaces and
converts them automatically.

## Expected output

- Predicted disease name
- Confidence percentage (from `predict_proba`)
- Top-3 likely conditions with probabilities
- If confidence is under 60%, a list of commonly co-reported symptoms for
  the predicted disease, so you can refine your input
- Description, recommended diet, and precautions — the knowledge base now
  covers all 41 diseases the model can predict (see below)

## Knowledge base coverage

All 41 diseases the model can predict now have a description, dietary
guidance, and precautions in `backend/knowledge_base.py`. The original 4
entries from the notebook (Fungal infection, Common Cold, Malaria,
Diabetes) are unchanged; the other 37 were added in the same style. This
is general educational information, not medical advice — always confirm
with a healthcare professional.

## Troubleshooting

**"Model artifacts not found" error on startup**
Run `python train_model.py` first — the app expects `models/*.pkl` to
already exist.

**`ModuleNotFoundError: No module named 'streamlit'` (or sklearn/pandas)**
Run `pip install -r requirements.txt` in the environment you're using to
launch the app.

**Predictions seem off for symptoms typed as free text**
Make sure symptom names match the dataset's naming (underscores, e.g.
`stomach_pain`). Unrecognized entries are ignored and listed in an info
banner rather than causing an error.

**Port already in use**
Run `streamlit run app.py --server.port 8502` (or any free port).

## Configuration

No API keys or external database service required. Accounts and history
use a local SQLite file (`data/app.db`) created automatically on first run —
nothing to configure.
